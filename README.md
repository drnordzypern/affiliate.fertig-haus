# Fertig Haus Partner Portal — Frontend

The public, Partner-facing frontend for the future Fertig Haus Partner
Portal, intended for `https://affiliate.fertig-haus.net`. This repository
is the frontend/BFF side of the architecture; `saleschain-os` remains the
backend source of truth for Partner data, referrals, commissions,
authentication, and compliance.

## Current preview scope

This is a **frontend foundation and visual preview**, not a production
system. Concretely:

- All pages render real, professional German copy and a finished visual
  design — nothing here is a wireframe.
- No page calls a backend, database, or SalesChain. There is no BFF
  implementation yet.
- The Partner application form, invitation-acceptance flow, and Partner
  portal are **non-functional previews**, clearly labelled as such in the
  UI, with submission/authentication intentionally disabled.
- No real Partner, lead, referral, or commission data exists or is
  simulated anywhere in the app.
- The site is configured to not be indexed by search engines
  (`app/robots.ts` plus `robots` metadata) until a real portal is
  approved and launched.

See [`docs/architecture.md`](docs/architecture.md) for the full
architecture boundary and the security rules that future integration work
must follow.

## Architecture

```text
Browser
→ affiliate.fertig-haus same-origin BFF   (not implemented yet)
→ SalesChain public/API boundary          (not connected)
→ SalesChain database and business logic  (source of truth)
```

This repository owns the browser-facing UI and will own the same-origin
BFF routes that mediate calls to SalesChain. It does not and will not own
Partner business logic, persistence, or SalesChain credentials on the
client.

## Local setup

Requires Node.js **24+** (a currently maintained Node release — Node 20
reached end-of-maintenance and is not supported) and npm.

```bash
npm install
npm run dev
```

The app runs at `http://localhost:3000`.

## Environment variables

See [`.env.example`](.env.example) for the full list with explanatory
comments. **Names only — no values are set, and none should be
committed.**

- `SALESCHAIN_API_BASE_URL` — server-only, SalesChain boundary base URL
- `SALESCHAIN_BFF_CREDENTIAL` — server-only, must never reach the browser
- `NEXT_PUBLIC_TURNSTILE_SITE_KEY` — intentionally public (Turnstile site
  key)

## Security boundaries

- SalesChain is the sole source of truth for Partner applications,
  invitations, authentication/authorization, referrals, leads,
  commissions, verification, and audit/compliance. None of that logic is
  duplicated here.
- No database, cache, or persistence layer belongs in this repository at
  this stage.
- The browser will only ever talk to this app's own origin. A same-origin
  BFF (not yet built) is the only thing allowed to call SalesChain.
- Server-only credentials (see `.env.example`) must never be exposed to
  the browser, logged, or embedded in a `NEXT_PUBLIC_*` variable.
- Future invitation tokens must be carried in URL fragments, never query
  strings, and must never be logged, sent to analytics, or persisted in
  browser storage.

Full detail: [`docs/architecture.md`](docs/architecture.md).

## What is intentionally not implemented

- Any connection to `saleschain-os` or a real SalesChain environment
- A working Partner application submission
- Invitation token reading, validation, or acceptance
- Login, sessions, or authentication of any kind
- Referral/QR attribution, lead tracking, or commission calculation
- A same-origin BFF or any backend route handlers
- Analytics, tracking pixels, or a cookie banner (none are needed — no
  tracking exists yet)
- A sitemap (would claim indexable, finished routes; none exist yet)
- Final, legally reviewed Impressum/Datenschutz copy or links

## Next integration steps

1. Get the SalesChain authentication/API contract reviewed and approved.
2. Implement same-origin BFF route handlers that hold
   `SALESCHAIN_BFF_CREDENTIAL` server-side and proxy to
   `SALESCHAIN_API_BASE_URL`.
3. Implement fragment-only token extraction and immediate fragment
   scrubbing for `/partner/invitation/accept`, plus Turnstile and a real
   accepted/unavailable state, per the structure documented in
   [`components/invitation/InvitationAcceptShell.tsx`](components/invitation/InvitationAcceptShell.tsx).
4. Wire `/partner-werden` to a real, Turnstile-protected BFF submission
   endpoint once the application data contract is approved.
5. Replace the `/portal` preview with an authenticated view backed by real
   SalesChain data once auth exists.
6. Replace the temporary text wordmark
   ([`components/brand/Wordmark.tsx`](components/brand/Wordmark.tsx)) with
   the approved logo, and add an approved favicon (`app/icon.png` or
   `app/favicon.ico`) — none is set today, so browsers fall back to their
   own default tab icon rather than showing unrelated Next.js branding.
7. Supply final, legally reviewed Impressum/Datenschutz links in
   [`lib/legal-config.ts`](lib/legal-config.ts).
8. Re-enable indexing (`app/robots.ts`, `robots` metadata in
   `app/layout.tsx`) and add a sitemap once the portal is approved for
   launch.

This project is a frontend foundation only and is **not** production
ready.
